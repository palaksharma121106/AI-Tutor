# AI Tutor (Streamlit + Groq)

An AI-powered tutor: enter any topic and get a tailored explanation, key
points, a real-world example, an auto-generated runnable **code example**
(for technical topics), a **quiz** with scoring, a **follow-up question**,
and an interactive **Plotly chart with a written insight** explaining what
it means — generated by `llama-3.1-8b-instant` via the Groq API.

You can also personalize it from the sidebar: tell it what course/subject
you're studying and your level (Beginner/Intermediate/Advanced), and the
explanation, examples, and code get tailored to that context.

## Project Structure

```
ai-tutor/
├── main.py           # Streamlit UI ONLY (input, buttons, display)
├── utils.py          # ALL logic — prompt building, Groq calls, JSON parsing
├── requirements.txt  # Dependencies
├── .env.example       # Copy to .env and add your real key
└── .env               # (you create this) holds GROQ_API_KEY — never commit it
```

## Setup (VS Code / terminal)

1. **Create a virtual environment** (recommended):
   ```bash
   python -m venv venv
   # Windows:
   venv\Scripts\activate
   # Mac/Linux:
   source venv/bin/activate
   ```

2. **Install dependencies**:
   ```bash
   pip install -r requirements.txt
   ```

3. **Add your Groq API key**:
   - Copy `.env.example` to `.env`
   - Get a free key at https://console.groq.com/keys
   - Edit `.env`:
     ```
     GROQ_API_KEY=gsk_your_actual_key_here
     ```

4. **Run the app**:
   ```bash
   streamlit run main.py
   ```
   This opens the app in your browser (usually at `http://localhost:8501`).

## Testing utils.py independently (notebook-style)

Since `utils.py` has no Streamlit dependency, you can test the whole
pipeline directly from the terminal:

```bash
python utils.py
```

This runs the built-in test block at the bottom of the file, which calls
`get_tutor_response("Recursion")` and prints every section to the console —
useful for debugging prompts or the Groq call without touching the UI.

You can also test individual functions in a Python shell or Jupyter:

```python
from utils import build_prompt, call_llm, parse_response, get_tutor_response

prompt = build_prompt("Binary Search")
print(prompt)

raw = call_llm(prompt)
print(raw)

data = parse_response(raw)
print(data["explanation"])
```

## How it Works

1. `main.py` collects the topic, plus optional course context and level,
   from the sidebar/input via Streamlit widgets.
2. On button click, it calls
   `utils.get_tutor_response(topic, course_context, level)`.
3. Inside `utils.py`:
   - `build_prompt(...)` builds a structured prompt asking for strict JSON,
     including a `code_example` block and a `graph_insight` explanation.
   - `call_llm(prompt)` sends it to Groq's chat completion endpoint.
   - `clean_json_text()` strips any markdown fences/stray text.
   - `parse_response()` turns it into a Python dict, with safe fallbacks
     (including nested defaults for `code_example`).
4. `main.py` renders everything in tabs: Explanation, Code (only shown
   when the topic is technical and code was generated), Quiz, Visual
   Insight (Plotly bar chart + written explanation), and Go Deeper
   (follow-up question).

## Notes

- If the model ever returns malformed JSON, `parse_response()` falls back
  to a safe empty structure so the app won't crash — you'll see a message
  asking you to try again.
- Quiz state is scoped per-topic via Streamlit's `key=` parameter, so
  generating a new topic resets the quiz correctly.
- The "Code" tab only appears when the AI actually returned a non-empty
  code snippet — for purely conceptual topics (e.g. Photosynthesis) it's
  automatically skipped.
- The AI decides `topic_type` ("technical" vs "conceptual") itself based
  on the topic, and is instructed to always produce real, runnable code
  for technical topics.
